## 1. 結論
OutSystems 11 の OrderManagement を Next.js 15 + PostgreSQL 16 で作り直しました。O11 実機と同じユーザー・同じ画面の 13 組を並べて比べ、**データ件数・一覧の内容と並び・金額・業務ルール・メッセージが一致すること**を確認しました。差異は下の表の 6 点で、どれも意図した改善か表示上の違いです。O11 側のアプリとデータは変更していません（読み取りと画面表示のみ）。

## 2. 作業の流れ
1. Windows に Service Studio 11.55.94 を入れ、`personal-pimir0dg` に接続して O11 MCP を起動
2. MCP で `OrderManagement_CS`（エンティティ 15・サーバーアクション・ロール・リソース 7 個）と `OrderManagement`（15 画面・ブロック・アクション）を取得
3. Sample Users の 3 名（Manuel / Ana / José）で実機を操作し、全画面を撮影。JS エラーも記録
4. 仕様書と移行設計書を作成
5. Next.js + PostgreSQL で実装。O11 の Bootstrap 用 xlsx / zip（MCP の getResource で取り出したもの）をそのまま seed に使用
6. O11 実機と Next.js を並べて比較し、ずれを直す（2 回）
7. 単体テスト・E2E テスト・ビルド

## 4. 差異（意図したもの・表示上のもの）

| # | 内容 | O11 | Next.js | 理由 |
|---|---|---|---|---|
| D1 | ダッシュボードのグラフ | `H.each is not a function` で描画に失敗（軸と凡例だけ） | SVG で描画し、値も表示 | O11 の実行時エラーを直した |
| D2 | Top performers の表記 | €2.719k | €2,719k | O11 は区切り文字の引数が逆。値は同じ |
| D3 | Goal の Current | 進捗の部品の中に表示（テキストとしては取れない） | 「Current €41k (82%)」 | 式は同じ（仕様書 §5.2） |
| D4 | ダッシュボードの Draft 一覧の並び | ORD0043〜0057（Planty）が先頭 | ORD0004 から | どちらも UpdatedOn の昇順。O11 側の UpdatedOn の実値は MCP で読んでいないので未確認。件数・内容は一致 |
| D5 | Bootstrap のパスワード | `outsystems` でログインできない | ログインできる | 移行版ではパスワードを bcrypt で保存 |
| D6 | 在庫の更新 | 明細の保存と在庫の更新が別々の呼び出し | 1 トランザクション | 途中で失敗したときに在庫がずれないようにした |

### 画面操作の確認で見つかり、直した点
録画しながらの確認で次の 3 点が見つかりました。

| 内容 | 対応 |
|---|---|
| Next.js の ProductDetail で Edit を押すと、編集モードに入らずにそのまま保存されていた | 直した（Edit と Save のボタンを別の要素にした）。E2E を追加 |
| 担当者の注文詳細に Submit が表示されていた。O11 では出ない | O11 では Submit ボタンが `If_IsOrderManager` の中にある [MCP]。Next.js もマネージャーにだけ表示するよう直した |
| Bankpeer の Email が元データで「4200」のため、編集画面で保存できない | O11 の AccountEdit も Email 欄が `InputType.Email` なので [MCP]、O11 と同じ動きと判断して変えていない。元データの癖 |

O11 の計算上の癖（Top 5 Categories が昇順で下位 5 件、Top performers の式が約 100 倍、Order Sales が 2020 年固定、検証メッセージのずれ）は、一致させるためにそのまま再現しています。修正案は設計書 §8 にあります。
