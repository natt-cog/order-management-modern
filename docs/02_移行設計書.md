# OrderManagement 移行設計書（OutSystems 11 → Next.js + PostgreSQL）

前提: 現行の仕様は [01_仕様書.md](01_仕様書.md) のとおり。方針は「**見た目と業務ルールを O11 と同じにし、O11 側の実行時エラーだけを直す**」。計算式の癖は同じにしたうえで、修正案を §8 にまとめます。

## 1. 構成

```mermaid
flowchart LR
  B[Browser] -->|HTTP / Server Actions| N[Next.js 15 App Router<br/>React Server Components]
  N -->|Drizzle ORM / postgres.js| P[(PostgreSQL 16)]
  S[scripts/seed.ts] -->|O11 の xlsx / zip を読む| P
  subgraph N
    UI[src/app/(app)/* 画面] --> Q[src/lib/queries/* 参照系]
    UI --> SA[actions.ts Server Actions] --> SV[src/lib/services/* 更新系・検証]
    SV --> R[src/lib/rules.ts 採番・金額式・例外]
    A[src/lib/auth.ts JWT Cookie・ロール]
  end
```

| 項目 | 採用 | 理由 |
|---|---|---|
| フレームワーク | Next.js 15（App Router、TypeScript） | 画面とサーバー処理を 1 つのリポジトリで持てる。O11 の Screen + Server Action の形に近い |
| DB | PostgreSQL 16 | 要件どおり |
| ORM | Drizzle ORM / drizzle-kit | スキーマを TypeScript で書ける。SQL に近く、O11 の Aggregate を 1 対 1 で書き直しやすい |
| 認証 | `jose` の JWT を HttpOnly Cookie `om_session` に入れる + `bcryptjs` | O11 の Login / Login_SampleUser / CheckXxxRole を置き換える |
| 検証 | Server Actions の中でチェックし、O11 と同じメッセージを返す | 画面側・サーバー側の両方の検証を 1 か所にまとめる |
| テスト | Vitest（単体）・Playwright（E2E） | |

## 2. モジュールの対応

| O11 | Next.js |
|---|---|
| OrderManagement_CS の Entities / Static Entities | `src/db/schema.ts`（Drizzle）、`drizzle/` マイグレーション |
| CS の Server Actions（Order_Save、OrderItem_Save、*_Validate、*_GenerateCode） | `src/lib/services/{orders,accounts,products}.ts`、`src/lib/rules.ts` |
| UI の Aggregates（画面ごとのデータ取得） | `src/lib/queries/{dashboard,orders,products,accounts}.ts` |
| UI の Screen | `src/app/(app)/<route>/page.tsx`（Server Component） |
| UI の Client Action / Form | `"use client"` コンポーネント（`OrderEditor.tsx`、`ItemPanel.tsx`、`ProductForm.tsx`、`AccountForm.tsx`） |
| UI 側の Server Action（SaveOrderItemandUpdateStock など） | 各画面の `actions.ts`（`"use server"`） |
| Roles / CheckRole | `src/lib/auth.ts` の `requireRole()`、`user_roles` テーブル |
| SiteProperties / Client 変数 | `site_properties` テーブル（CompanyGoal = 70 も明示的に持たせる） |
| Timer Application_Bootstrap + Resources | `scripts/seed.ts` + `data/outsystems-resources/`（MCP の getResource で取り出した原本） |
| Menu / Layout ブロック | `src/app/(app)/layout.tsx` |
| Charts（OutSystems Charts） | `src/components/dashboard.tsx` の SVG 棒グラフ・面グラフ |
| Binary の画像表示 | `src/app/api/pictures/[id]`、`src/app/api/products/[id]/cover` |

| Dashboard | `/dashboard`（Manager は `/dashboard-manager` に移動） | Rep / Manager |
| DashboardManager | `/dashboard-manager` | Manager |

| OrderDetail | `/orders/[id]`、新規は `/orders/new?account=&opportunity=` | Rep / Manager |

## 4. データ移行（テーブル対応）

| O11 エンティティ | PostgreSQL テーブル | 型の対応 |
|---|---|---|
| (Users) / (Role) | `users`、`user_roles` | パスワードは bcrypt |
| Account / Country | `account` / `country` | Text(n) → varchar(n)、PhoneNumber / Email → varchar |
| Opportunity / OpportunityType / OpportunityStage | `opportunity` / `opportunity_type` / `opportunity_stage` | Currency → numeric(37,8) |
| Order / OrderStatus | `order` / `order_status` | Decimal(37,8) → numeric(37,8)、Date → date、DateTime → timestamp |
| OrderItem | `order_item` | Amount は numeric(37,8) で丸めない |
| Product / ProductCategory / Brand / Model / ProductFeature / ProductPicture | `product` / `product_category` / `brand` / `model` / `product_feature` / `product_picture` | Binary → bytea。Discount は割合のまま |
| SiteProperty | `site_properties` | key / value |

Static Entity は Id を O11 と同じ値で固定して投入します（OrderStatus 1〜4 など）。コードの中では `OrderStatus.Draft` のような定数で参照します。

`scripts/seed.ts` は Application_Bootstrap と同じ順番・同じ規則（小文字化、コードの振り直し、全件 Draft、`ChangeSalesRep` を行ごとに切り替え）で投入し、件数と担当者の振り分けが O11 と同じになることを確認済みです（仕様書 §4.2）。

## 5. 業務ロジックの移し方

| O11 | Next.js | 備考 |
|---|---|---|
| Order_Save の権限チェック | `saveOrder()` の最初で `requireRole` + `PermissionException` | メッセージは同じ |
| ステータスを変えられるのは Manager か同じステータスのとき | `setOrderStatus()` | Submit は担当者、Approve / Reject は Manager |
| TotalAmount = 有効な明細の合計 | `recalcTotal()`（SQL の sum。numeric のまま） | |
| OrderItem の金額式 | `amountOf(price, qty, discount)` | |
| 在庫の増減（SaveOrderItemandUpdateStock / UpdateStockOnOrderDelete） | `saveOrderItem()` / `deleteOrderItem()` / `deleteOrder()` の中で**同じトランザクション**で更新 | O11 は別々のアクション呼び出しだった。途中で失敗したときに在庫だけずれることがなくなる |
| 採番（*_GenerateCode） | `nextCode(prefix, maxCode)` | 同時に登録すると重複する可能性は O11 と同じ。§8 で一意制約を提案 |
| InvalidArgumentsException | `InvalidArgumentsException`（`rules.ts`）→ 画面にメッセージを表示 | |
| 画面側の入力チェック（ProductDetail など） | `validateProductForm()` などで、サーバー側でも同じメッセージを返す | |
| Login_SampleUser | `loginSampleUser()`（3 名の許可リスト `sample-users.ts`） | デモ用の機能として残す。本番ではオフにする想定 |

## 6. 表示の決まりごと
- 金額: `€` + 3 桁区切り + 小数 2 桁。丸めは O11 と同じ「倍精度の値で `toFixed(2)`」（20629.405 → €20,629.40）
- k 表記（PrettyFormatCurrency）: 1000 以上は `€{n/1000}k`。区切り文字は正しい向きにする（O11 の €2.719k → 移行版 €2,719k）
- 日付: 一覧は `9 Apr 2020` 形式。OrderDetail・OpportunityDetail は O11 と同じく書式なし（`2020-04-09`、`2020-04-01 00:00:00`）。OpportunityDetail の Amount・Probability も O11 と同じく書式なし（`1675`、`53`）
- 一覧件数: 「1 to 20 of 58 items」、Catalog は「12 of 28 products」

## 7. 同等性の確認方法（パリティテスト）
1. **データ**: seed 後の件数・担当者別の件数・注文合計を、O11 の MCP `runQuery` と実機の画面の値と比べる
2. **画面**: O11 と Next.js で同じユーザー・同じ操作をして、画面のテキスト（件数・並び・金額・メッセージ）を比べ、スクリーンショットを並べる
3. **シナリオ**（Playwright `tests/e2e/parity.spec.ts`）:
   - 担当者 / Manager のログインと着地する画面、権限のない画面の拒否
   - Orders の件数・既定の並び・金額表示・金額レンジ・検索
   - 注文の新規作成（Account 未入力のエラー）→ 明細の追加（在庫超過のエラー、割引の計算）→ Submit → Manager が Approve
   - Catalog の 12 件表示と Load more、Invoices の空表示
4. **単体テスト**（Vitest `tests/unit`）: 採番、金額式、Final price、金額表示の丸め、k 表記
5. 結果は [03_報告書.md](03_報告書.md) の比較表に「一致 / 差異（意図したもの）/ 未確認」で記録する

## 8. O11 の不具合への対応方針と修正案

| # | O11 の挙動 | 移行版（今回） | 修正案（次の段階） |
|---|---|---|---|
| 1 | グラフで `H.each is not a function` | SVG で描画して解消 | — |
| 2 | Order Sales が 2020 年に固定 | 同じ | 対象期間を「当年」か画面で選べるようにする |
| 3 | Top 5 Categories が昇順・式が約 100 倍 | 同じ | `orderBy(desc)`、式を `Price*Qty*(1-Discount/100)`（= OrderItem.Amount）に |
| 4 | Top performers の式が約 100 倍 | 同じ | 同上 |
| 5 | k 表記の区切り文字が逆 | 修正済み | — |
| 6 | 検証メッセージのずれ | 同じ | 条件に合ったメッセージに直す |
| 7 | 採番が max + 1 で、同時登録時に重複しうる | 同じ | `code` に一意制約 + シーケンスにする |
| 8 | 在庫の更新が別のアクション呼び出し | 1 トランザクションに改善 | — |

修正案は、O11 との一致を確認した後で別の PR として入れる想定です（一致確認と仕様変更を混ぜないため）。
